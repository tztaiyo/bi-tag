# 受入・検査 タグ管理(デモ版)

部品タグ・台車/パレットタグ・置き場所タグをスマホのカメラで連続して読み、「どの部品が・どの台車に載って・どこにあり・どの状態か」を管理画面(PC)で共有するアプリです。

登録は **① 部品(品名) → ② 台車・パレットの番号 → ③ 置き場所** の順にタグをかざすだけです。

- **タップで確定**: カメラがQRを読むと候補カードが出るだけで、タップするまで何も変わりません。タップしなければ4秒で消えます。白い枠の中で2回続けて読めたものだけを候補にします(となりのタグの誤読を防ぐ)。
- **登録のしかた(自動/手動)**: 現場アプリ右上の「登録」で切り替え。自動 = 3つそろった瞬間に登録。手動 = そろうと「登録する」ボタンが出て、押したときに登録(取消ボタンはなく、次のタグを読めば入れ替わる)。
- **計画(仮)**: 管理画面の「計画」で、品番ごとに載せる台車・置き場所を決めておくと、違う台車・置き場所では**エラーになり登録されません**(管理画面にも「計画外を検知」が届く)。どうしても置くときは「計画外として登録する」。
- **二重登録の防止**: 登録済みの部品を同じ台車・置き場所でもう一度読んでも送信しません(青で「登録済み」)。別の台車・置き場所で読むと「移し替えますか?」と確認します(自動でも確認)。同じステータス(検査済→検査済)も送りません。台車の欄には載っている点数が出ます。
- **デモをリセット**: 管理画面「現場の状況」右上(または「設定」)の「デモをリセット」で、登録の記録をすべて消してはじめからにできます(タグ・台車・置き場所は残る。計画を仮の計画に戻すことも可)。現場のスマホも数秒で自動的にリセットされます。
- **読みやすさ・音声**: エラーや「登録済み」は画面下半分の大きなお知らせ画面(記号 ○ ✕ ✓ と言葉で区別)と、女性の音声で知らせます。画面上の「音声」「文字(大/特大)」で切り替え。お知らせ画面はタッチ・次のタグ・時間で閉じます。
- **固定と解除**: 台車と置き場所は読むと固定。それぞれの欄をタップすると、別々に解除できます。台車と置き場所は一度読むと固定されるので、同じ台車に載せる部品は部品タグを続けてかざすだけで記録されます。部品を読まずに「台車 → 置き場所」と読むと、台車ごとの移動(載っている部品もいっしょに移動)として記録されます。

| アプリ | URL | 使う人 |
| --- | --- | --- |
| 現場アプリ | `https://<GitHubアカウント>.github.io/<リポジトリ名>/` | 現場のスマホ。タグを連続でスキャン |
| 管理アプリ | `https://<GitHubアカウント>.github.io/<リポジトリ名>/admin.html` | 事務所のPC。置き場マップ・通信の様子・優先アラート |

## 業務の流れ(2つに分けています)

**① 入荷 → 入庫**(入庫待ち(検査済)で終わり。「保管」は概念上だけで、システムにはありません)
未受入 →(台車に載せる)→ 未検査 →(台車ごと検査机の隣へ・検査)→ 検査済(パレットに載る)→(パレットごと入庫前へ)→ **入庫待ち(検査済)**

**② 出庫 → 出荷**(計画から来る「今日の出庫予定」から始まる)
出庫予定 →(棚出し: パレットに載せて出庫仮置きへ)→ 仮置き →(出庫で読む)→ 出庫済 →(パレットごと補用仮置き・補用検査机へ)→ 補用未検査 →(読む)→ 補用検査済 →(包装仮置きへ)→ 包装待ち →(包装作業場へ)→ 包装前 →(読む)→ 包装済 →(入庫前へ)→ **入庫待ち(包装済)**
(出荷の前に包装だけ済ませて、また入庫するイメージ)

- **台車とパレット**: 台車は未検査品を検査机の隣へ運ぶまで。検査済はパレット(P-01, P-02 … と番号つき)に載り、その先はずっとパレットで運びます。使い方は台車と同じで、どの工程でも「② 台車・パレット → ③ 置き場所」と読むと、載っている部品ごと移動します。
- **完了%**: ① ② それぞれ、段階ごとの完了%をスマホ上部(「進み具合」)と管理画面「現場の状況」に表示します。
- **② 用のデモデータ**: 「今日の出庫予定」(S0001〜S0006)は ① とは独立。① をやらなくても、すぐ ② を見せられます。管理画面の「今日の出庫予定」と「タグ発行」の下に一覧があります。
- **計画はステータスに合わせて進む**: 受入の計画(台車・置き場所)は受入のあいだだけ。そのあとは、いまのステータスで行ける場所が決まっていて、違う場所に運ぶとエラー。部品一覧とスマホに「いまの予定」が出ます。
- **保留は計画から**: 「保留」と「備考(理由)」は計画から入ってきます(現場・PCでは選びません)。保留の部品は読んだ時点で「検査しないで、保留棚へ」。保留棚は決まった場所の棚で、専用の保留棚タグを貼り、**部品 + 保留棚**の2つで登録します。
- **出庫のときのQR**: 一部だけ出庫すると、パレットから離れる残りに新しいタグを発行し、**未入庫**に戻します(計画側で扱う)。まとめて出庫すると新しいタグ1枚、元のタグは無効。新しいタグはPCで印刷して貼り、読んで貼付確認。
- **リードタイム**: ① 入荷→入庫(最初の受入 → 入庫待ち(検査済))、② 出庫→出荷(棚出し → 入庫待ち(包装済))を自動で計測。管理画面「リードタイム」で確認、「スプレッドシートに書き出す」で保存(現場には出しません)。
- スマホは上部で「① 入荷→入庫」「② 出庫→出荷」を切り替え。次にすることは「次の作業」に自動で出ます(PCの指示はいりません)。

## アクセス制限

- 画面を開いても、**許可されたGoogleアカウントでログインするまで中身は何も表示されません**(ログイン画面だけ)。
- データはあなたのGoogleスプレッドシートにあり、**スプレッドシートを共有された人しか読み書きできません**。共有されていないアカウントでログインすると「権限がありません」と表示されます。
- さらに、Google Cloud の「テストユーザー」に登録した人しかログインそのものができません(二重の制限)。
- リポジトリにはアプリだけが入り、データ・スプレッドシートのID・クライアントIDは入りません(管理画面で入力し、PCに保存。スマホにはQRで渡します)。

## 準備(最初に一度だけ・約15分)

### 1. GitHub Pages にアプリを置く
1. GitHub で新しいリポジトリを作る(例: `bi-tag`、Public)
2. このフォルダの中身(`index.html` `admin.html` `config.js` `sw.js` `manifest.webmanifest` `icon-*.png` `.nojekyll`)をアップロード
3. リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save
4. 数分で `https://<アカウント>.github.io/<リポジトリ名>/` が開けるようになります

### 2. Google スプレッドシートを作る
1. 個人の Google アカウントで空のスプレッドシートを作成(名前は自由。例: 受入検査タグ管理)
2. 右上「共有」で、使う人のアカウントを「編集者」で追加
3. URL を控えておく(表の作成はアプリが自動で行います)

### 3. Google Cloud でログイン用のIDを作る
1. https://console.cloud.google.com/ で新しいプロジェクトを作成(例: bi-tag)
2. 「APIとサービス」→「ライブラリ」で **Google Sheets API** を有効にする
3. 「OAuth 同意画面」: 対象 = 外部、アプリ名 = 受入検査タグ管理、公開ステータスは「テスト」のまま。**テストユーザーに、使う人のGoogleアカウントを追加**
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」: 種類 = ウェブ アプリケーション、**承認済みの JavaScript 生成元** = `https://<アカウント>.github.io`
5. 表示された **クライアントID**(`…apps.googleusercontent.com`)を控える

### 4. 管理画面の最初の設定
1. PCで `…/admin.html` を開き、クライアントIDとスプレッドシートのURLを入れて「保存して次へ」
2. 「Googleでログイン」(テスト中のアプリのため「Googleはこのアプリを確認していません」と出たら「続行」)
3. 「デモ用のタグ・台車・置き場所を作る」→「タグ発行」「台車・置き場所」から印刷

### 5. スマホをつなぐ
管理画面の「現場端末」に出るQRをスマホで読み、Googleでログインして端末名を入れます。ブラウザの「ホーム画面に追加」でアプリのように使えます。

## デモの流れ

`kit/` にデモ資料とタグがあります(このリポジトリには入っていません。別にお渡しした一式を参照)。

- **① 入荷→入庫**: 「デモ資料_①入荷→入庫.pdf」。受入(台車) → 保留棚 → 台車ごと検査机へ → 検査(パレットへ) → パレットごと入庫前へ
- **② 出庫→出荷**: 「デモ資料_②出庫→出荷_出庫予定.pdf」。① とは別に、今日の出庫予定 S0001〜 で 棚出し → 出庫(分ける・まとめる) → 補用検査 → 包装 → 入庫前へ
- そのほか: 優先アラート(PC「優先アラートを受信(デモ)」)、機内モードでのスキャン(送信待ち → 自動で送信)

## 補足

- Google の利用回数の上限は「1人あたり1分60回」です。PCとスマホは別のアカウントにすると余裕があります(同じアカウントでもデモ程度なら収まります)。
- ログインの有効期限は約1時間です。切れると画面上部に「ログイン」ボタンが出ます(その間のスキャンは端末に保存され、ログイン後に送られます)。
- タグのQRには品番・ロット・優先かどうか(台車・場所タグは優先台車・優先置き場かどうか)が入っているので、電波のない場所でも優先品は判定できます。
- 以前の版で「置き場所(種別=台車)」として登録した C-01 などは、そのまま台車として扱われます。
- `_src/` はアプリの元のソースです(`build.py` で `index.html` / `admin.html` を作り直せます)。
